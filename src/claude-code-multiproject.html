📦方式一：Homebrew（推荐）

bash · macOS Homebrew
# ① 安装 Homebrew（如未安装）
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Apple Silicon (M1/M2/M3/M4) 需要额外配置 PATH

# ③ 验证 Node.js 版本（需 ≥ 18）

# ⑥ 配置 API（以 DeepSeek 为例）

export ANTHROPIC_AUTH_TOKEN="your_api_key"
claude

💾永久写入 API 配置

bash · ~/.zshrc 永久配置
# 打开配置文件
open -e ~/.zshrc   # 用 TextEdit 编辑
# 或用命令行编辑器
nano ~/.zshrc

# 追加以下内容（以 DeepSeek + 通义千问双配置为例）
# ──────────────── Claude Code 配置 ────────────────
export DEEPSEEK_API_KEY="sk-your-deepseek-key"
export QWEN_API_KEY="sk-your-qwen-key"

# 默认使用 DeepSeek
export ANTHROPIC_BASE_URL="https://api.deepseek.com/anthropic"

export ANTHROPIC_MODEL="deepseek-chat"
export API_TIMEOUT_MS=600000

# 快速切换函数
function cc-deepseek() {
  export ANTHROPIC_BASE_URL="https://api.deepseek.com/anthropic"
  export ANTHROPIC_AUTH_TOKEN="$DEEPSEEK_API_KEY"
  export ANTHROPIC_MODEL="deepseek-chat"
  echo "✅ Claude Code → DeepSeek V3"
}
function cc-qwen() {
  export ANTHROPIC_BASE_URL="https://dashscope.aliyuncs.com/apps/anthropic"
  export ANTHROPIC_API_KEY="$QWEN_API_KEY"
  export ANTHROPIC_MODEL="qwen3-coder-plus"
  echo "✅ Claude Code → Qwen3-Coder"
}
# ─────────────────────────────────────────────────

# 使配置立即生效
source ~/.zshrc
⚠️
Apple Silicon 常见问题：若 npm 提示 EACCES permission denied，请勿用 sudo npm install。正确做法是通过 nvm 或 Homebrew 管理 Node.js，权限由用户目录完全控制，无需 root。

# ── STEP 5：启动 ──

ℹ️
WSL2 中访问 Windows 项目文件：Windows 的 C 盘挂载在 WSL2 的 /mnt/c/ 路径下。例如 Windows 的 C:\Users\你\projects\myapp 在 WSL2 中是 /mnt/c/Users/你/projects/myapp。
建议将项目放在 WSL2 文件系统内（~/projects/）而非 Windows 盘，以获得更好的 I/O 性能。

会话管理基础单个项目内的会话切换与恢复

Claude Code 的会话（Session）存储在每个项目目录的 .claude/ 文件夹中，会话与项目目录绑定。

📋会话的工作原理

会话存储结构
项目目录结构 ~/projects/my-app/ ├── src/ ├── package.json └── .claude/ ├── settings.json ← 项目级配置 ├── settings.local.json ← 本地配置（不提交） └── sessions/ ← 会话历史 ├── session_abc123.json ← 历史会话1 ├── session_def456.json ← 历史会话2 └── session_current.json ← 当前会话 注意：.claude/sessions/ 建议加入 .gitignore

🔄恢复历史会话

claude session · 会话恢复命令
# 方式一：启动时直接进入会话选择器
claude --resume
# 会弹出交互式选择器，显示项目内所有历史会话

# 方式二：会话内使用 /resume 命令
/resume
# 选择器快捷键：↑↓ 选择，Enter 确认，R 重命名会话

# 方式三：从指定 PR 恢复（适合 Code Review 场景）
claude --from-pr 123
# 恢复与该 PR 关联的会话

# 实用建议：给会话起有意义的名字
# 在 /resume 选择器中按 R 重命名，方便以后识别

🧹上下文管理

claude session · 上下文控制
# 清空上下文（开始全新对话，适合切换任务）
/clear

# 压缩上下文（保留摘要，节省 token，适合长会话）
/compact

# 回退到之前某步（"时光机"功能）
/rewind
# 选择要回退的步骤，可在此基础上开启分叉会话

# 查看当前会话使用的模型和配置
/status
💡
实用技巧：使用 /rewind 可以在当前会话中创建"分叉"——回退到某个节点，然后尝试不同的解决方案，而不会丢失原来的对话记录。这对于探索多种实现方案非常有用。

多项目切换在不同代码库之间快速切换工作上下文

Claude Code 的会话是按项目目录隔离的。切换项目 = 切换目录，Claude 会自动加载该项目的历史会话和配置。

➡️方法一：cd 切换目录（最简单）

bash · 基础切换方式
# 项目 A（前端）
cd ~/projects/my-frontend
claude          # ← 自动加载此项目的会话和 CLAUDE.md

# 切换到项目 B（后端）
# 先退出当前 claude（Ctrl+C 或 /exit），然后
cd ~/projects/my-backend
claude          # ← 自动加载后端项目的会话

# 或者同时指定模型（不同项目用不同模型）
cd ~/projects/my-backend
claude --model qwen3-coder-plus

# 查看当前项目有哪些历史会话
ls .claude/sessions/   # 若目录存在
/resume               # 在 claude 内部选择

⚡方法二：多终端 / 多 Tab 并行

这是最直观的多项目同时工作方案：每个终端 Tab 运行一个项目的 Claude Code，互不干扰。

bash · 多 Tab 并行操作
# ── 终端 Tab 1：前端项目 ──
cd ~/projects/my-frontend
claude
# 在此 Tab 工作，claude 完全理解前端代码库

# ── 终端 Tab 2：后端项目 ──
cd ~/projects/my-backend
claude
# 完全独立的上下文，互不影响

# ── 终端 Tab 3：基础设施 ──
cd ~/projects/infra-config
claude

# 工具推荐：
# macOS：iTerm2（Cmd+D 水平分屏，Cmd+Shift+D 垂直分屏）
# Linux：tmux / Terminator / Tilix
# Windows：Windows Terminal（可配置多个 WSL2 Tab）

🖥️方法三：tmux 持久化多项目会话（Linux / macOS / WSL2）

tmux 让终端会话在关闭连接后依然存在，断开 SSH 后 Claude Code 继续工作。

bash · tmux 多项目管理
# 安装 tmux
brew install tmux           # macOS
sudo apt install tmux       # Ubuntu/Debian

# ── 为不同项目创建命名 tmux 会话 ──
tmux new -s frontend        # 创建名为 frontend 的会话
cd ~/projects/my-frontend && claude

# 快捷键：Ctrl+B, D  →  分离（Detach）当前会话

tmux new -s backend         # 新建 backend 会话
cd ~/projects/my-backend && claude
# Ctrl+B, D  →  分离

# ── 查看所有运行中的 tmux 会话 ──
tmux ls
# 输出：frontend: 1 windows (created...) [220x56]
#        backend:  1 windows (created...) [220x56]

# ── 重新连接到某个项目 ──
tmux attach -t frontend     # 回到前端项目
tmux attach -t backend      # 回到后端项目

# ── tmux 常用快捷键（Ctrl+B 前缀）──
# Ctrl+B D       分离当前会话
# Ctrl+B $       重命名当前会话
# Ctrl+B s       列出所有会话并切换
# Ctrl+B c       在当前会话新建窗口
# Ctrl+B w       切换窗口
# Ctrl+B %       左右分屏
# Ctrl+B "       上下分屏

🚀方法四：快速跳转脚本

写一个 Shell 函数，一键跳转到任意项目并启动 Claude Code：

bash · 写入 ~/.zshrc 或 ~/.bashrc
# ── 多项目快速启动函数 ──
# 用法：cc frontend / cc backend / cc infra

declare -A CLAUDE_PROJECTS=(
  [frontend]="$HOME/projects/my-frontend"
  [backend]="$HOME/projects/my-backend"
  [infra]="$HOME/projects/infra-config"
  [docs]="$HOME/projects/documentation"
)

function cc() {
  local project="$1"
  if [[ -z "$project" ]]; then
    # 无参数：列出所有项目
    echo "📂 可用项目："
    for key in "${!CLAUDE_PROJECTS[@]}"; do
      echo "  cc $key  →  ${CLAUDE_PROJECTS[$key]}"
    done
    return
  fi
  local dir="${CLAUDE_PROJECTS[$project]}"
  if [[ -z "$dir" ]]; then
    # 当作目录路径直接处理
    dir="$1"
  fi
  if [[ ! -d "$dir" ]]; then
    echo "❌ 目录不存在: $dir"; return 1
  fi
  echo "🚀 进入 $project → $dir"
  cd "$dir" && claude
}

# 使用示例：
# cc              ← 列出所有项目
# cc frontend     ← 跳转前端项目并启动 claude
# cc backend      ← 跳转后端项目并启动 claude
# cc ~/other-proj ← 直接用路径

Git Worktree 并行会话同一项目多分支同时运行 Claude Code

Git Worktree 是 Claude Code 最强大的工作流之一：同一个仓库同时在多个目录开发多个功能，每个目录运行独立的 Claude Code 实例，完全无冲突。

单目录 vs Worktree 对比
❌ 传统单目录： ✅ Git Worktree 并行： ┌─────────────────────────┐ ┌──────────────────────────────────────────┐ │ ~/projects/my-app/ │ │ ~/projects/my-app/ (main) │ │ 当前只能在一个分支 │ │ ~/projects/my-app-feat-auth/ (feature) │ │ Context Lost ❌ │ │ ~/projects/my-app-bugfix/ (hotfix) │ │ stash → checkout │ │ │ │ → restart AI │ │ 每个目录 = 独立分支 + 独立 Claude 实例 │ └─────────────────────────┘ │ 共享同一个 git 历史和对象库 │ └──────────────────────────────────────────┘ Tab 1: cd my-app && claude → 处理 main 分支任务 Tab 2: cd my-app-feat-auth && claude → 并行开发认证功能 Tab 3: cd my-app-bugfix && claude → 同时修复紧急 Bug

⚡Claude Code 内置 Worktree 支持（推荐）

bash · --worktree 标志（v2.1.50+）
# ── 一键创建 Worktree 并启动新 Claude 会话 ──
cd ~/projects/my-app   # 先进入主项目目录

# 创建名为 feature-payments 的 Worktree（短标志 -w）
claude -w feature-payments
# Claude 会自动：
# 1. 在 .claude/worktrees/feature-payments/ 创建目录
# 2. 创建 feature-payments 分支
# 3. 在该目录启动 Claude Code 会话

# 完整标志写法
claude --worktree feature-payments

# 如果不指定名称，Claude 会自动生成
claude --worktree

# 会话内中途决定需要隔离时，也可以 /worktree 命令创建
/worktree create feature-payments
💡
将 .claude/worktrees/ 加入项目 .gitignore，避免 worktree 内容被 git 识别为未跟踪文件：
echo ".claude/worktrees/" >> .gitignore

🔧手动管理 Worktree（更多控制）

bash · 手动 git worktree 操作
# ── 创建 Worktree ──
cd ~/projects/my-app

# 创建新分支 + 新工作目录（放在仓库同级）
git worktree add ../my-app-feature-auth -b feature/auth
git worktree add ../my-app-bugfix-login -b hotfix/login-bug

# 基于已有分支创建工作目录
git worktree add ../my-app-release release/v2.0

# ── 在各 Worktree 中启动 Claude ──
# Terminal Tab 1（主项目）
cd ~/projects/my-app && claude

# Terminal Tab 2（认证功能）
cd ~/projects/my-app-feature-auth
npm install          # 别忘初始化依赖！
claude

# Terminal Tab 3（紧急修复）
cd ~/projects/my-app-bugfix-login
npm install
claude

# ── 查看所有 Worktree ──
git worktree list
# 输出：
# /home/user/projects/my-app               abc1234 [main]
# /home/user/projects/my-app-feature-auth  def5678 [feature/auth]
# /home/user/projects/my-app-bugfix-login  ghi9012 [hotfix/login-bug]

# ── 完成后清理 Worktree ──
cd ~/projects/my-app
git worktree remove ../my-app-feature-auth
git branch -d feature/auth    # 可选：同时删除分支

# 批量清理已删除的 Worktree 引用
git worktree prune

🔀Worktree 内的会话恢复与跨 Worktree 切换

bash · 跨 Worktree 会话管理
# /resume 选择器会显示同一 git 仓库下所有 Worktree 的会话
/resume
# 可以在当前 Worktree 的 claude 中看到其他 Worktree 的历史会话

# 在同一 Worktree 创建"分叉实验"（不污染主会话）
/rewind      # 回退到某个步骤
# 然后尝试不同的解决方案

# 提交 Worktree 中的工作成果并创建 PR
cd ~/projects/my-app-feature-auth
git add -A
git commit -m "feat: add OAuth2 authentication"
git push -u origin feature/auth
gh pr create --title "Add OAuth2 authentication" --base main
⚠️
合并冲突预防：如果多个 Worktree 都修改了同一个文件（如 src/config.ts），合并时会出现冲突。最佳实践是：每个 Worktree 负责相对独立的功能模块，在任务分配给 Claude Code 时，明确告知"只修改 X 模块相关的文件"。

第三方管理工具让多项目 / 多会话管理更高效

CCManager
推荐
TUI 界面管理多个项目的多个 Claude Code 会话，支持自动发现所有 git 仓库，无需 tmux，显示每个会话的实时状态（active/busy/waiting）。
Claude Squad
tmux 用户
基于 tmux 的多 Claude Code 实例管理工具，每个实例在独立 tmux 窗格中运行，适合深度 tmux 用户，支持可视化监控所有并行任务。
ccswitch
轻量
专注于 Worktree 管理的 Go CLI 工具，解决频繁创建 / 删除 Worktree 的繁琐操作，一条命令完成创建、进入、启动 Claude Code 全流程。
GitButler + Hooks
无冲突
通过 Claude Code lifecycle hooks 与 GitButler 集成，可在同一工作目录运行多个 Claude Code 实例，自动按会话 ID 分配到不同分支，无需 Worktree。

高级工作流最佳实践真实开发场景的完整操作流程

🎯场景一：前后端分离项目同时开发

bash · 完整操作示例
# ── 项目结构 ──
# ~/projects/
# ├── my-app-frontend/  (React + TypeScript)
# └── my-app-backend/   (FastAPI + PostgreSQL)

# ── 每个项目准备 CLAUDE.md（关键！）──
cat > ~/projects/my-app-frontend/CLAUDE.md << 'EOF'
# 前端项目
## 技术栈：React 18 + TypeScript + Tailwind + Vite
## 启动：npm run dev（端口 5173）
## 构建：npm run build
## 注意：API 调用统一在 src/api/ 目录，BASE_URL = http://localhost:8000
EOF

cat > ~/projects/my-app-backend/CLAUDE.md << 'EOF'
# 后端项目
## 技术栈：Python 3.11 + FastAPI + SQLAlchemy + PostgreSQL
## 启动：uvicorn main:app --reload（端口 8000）
## 数据库：postgresql://localhost/myapp_dev
## API 文档：http://localhost:8000/docs
EOF

# ── 打开两个终端 Tab ──
# Tab 1（前端）
cd ~/projects/my-app-frontend && claude

# Tab 2（后端）
cd ~/projects/my-app-backend && claude

# 两个 Claude 实例完全独立，分别理解各自的代码库

🔥场景二：新功能 + 紧急 Bug 并行处理

bash · Worktree 并行完整流程
# ── 起点：正在开发新功能 ──
cd ~/projects/my-app
claude                                   # 已在 main 分支工作

# 突然：生产环境出现 P0 Bug！
# 不需要 stash，不打断当前 Claude 会话

# 在新 Tab 中，利用 Claude Code 内置 worktree 创建隔离环境
cd ~/projects/my-app
claude -w hotfix-payment-null-pointer
# Claude 自动创建 .claude/worktrees/hotfix-payment-null-pointer/
# 告诉这个 Claude：
# "修复 payment 模块的空指针异常，代码在 src/payment/processor.ts"

# ── Tab 1：继续新功能（不受干扰）──
# ── Tab 2：并行修复 Bug ──

# Bug 修复完成后，在 hotfix Tab 中：
git add -A && git commit -m "fix: resolve null pointer in payment processor"
git push && gh pr create --base main

# 清理 Worktree
cd ~/projects/my-app
git worktree remove .claude/worktrees/hotfix-payment-null-pointer
# 或在 claude 会话内：
/worktree remove hotfix-payment-null-pointer

📊场景三：多项目 tmux 全栈工作站

bash · tmux 多项目一键启动脚本
cat > ~/start-dev.sh << 'EOF'
#!/bin/bash
# 一键启动全栈开发环境（三个 Claude 实例并行）

SESSION="dev-workspace"
FRONTEND="$HOME/projects/my-app-frontend"
BACKEND="$HOME/projects/my-app-backend"
INFRA="$HOME/projects/infra-config"

# 如果会话已存在，直接连接
if tmux has-session -t $SESSION 2>/dev/null; then
  tmux attach -t $SESSION
  exit
fi

# 创建新 tmux 会话
tmux new-session -d -s $SESSION -n frontend -x 220 -y 56

# 窗口 1：前端 Claude Code
tmux send-keys -t $SESSION:frontend "cd $FRONTEND && claude" Enter

# 窗口 2：后端 Claude Code
tmux new-window -t $SESSION -n backend
tmux send-keys -t $SESSION:backend "cd $BACKEND && claude" Enter

# 窗口 3：基础设施
tmux new-window -t $SESSION -n infra
tmux send-keys -t $SESSION:infra "cd $INFRA && claude" Enter

# 返回第一个窗口并连接
tmux select-window -t $SESSION:frontend
tmux attach -t $SESSION
EOF

chmod +x ~/start-dev.sh

# 以后每次启动整个工作环境只需：
~/start-dev.sh

# tmux 窗口切换：Ctrl+B + 1/2/3 或 Ctrl+B + 窗口名首字母
